# Free, open-source password-reset mail for Air Agent

This stack runs **Stalwart Community Edition** (open-source mail server) on your
existing VPS. Unlike paid transactional mail APIs, it has no per-email vendor fee,
but hosting, DNS, monitoring, configuration and deliverability remain your
responsibility. It is **not** deployed automatically on GitHub pushes because
the live VPS already has web services on ports 80/443.

## Use a separate sending subdomain

**Recommended example for agent.llama2.com:**
- Sending domain: `notify.llama2.com` (do not replace any existing `llama2.com` MX)
- SMTP hostname: `mail.notify.llama2.com`
- Sender address: `no-reply@notify.llama2.com`
- SMTP host: `mail.notify.llama2.com`
- SMTP port: `587` (authenticated STARTTLS)
- SMTP username: `no-reply@notify.llama2.com`
- SMTP password: **unique secret created inside Stalwart; never in GitHub**

Use different domain names if you do not control `llama2.com`.

## Server steps

1. Check ports 25, 465 and 587 are available on your VPS, and allow these ports
   in the Hostinger/VPS firewall as needed. Port 25 outbound is required for
   direct email delivery. Hostinger publishes a limit of 5 messages per minute.
2. Start the **separate** stack from the repository root:
   `docker compose -f deploy/mail/docker-compose.yml up -d`
   or create a *separate* Docker Compose project in Hostinger Docker Manager
   using this file. **Do not replace the Air Agent project's existing Compose.**
3. Stalwart's temporary admin credentials appear in its first bootstrap logs:
   `docker compose -f deploy/mail/docker-compose.yml logs stalwart`.
   Treat these credentials as secrets.
4. Open the setup wizard through an SSH tunnel:
   `ssh -L 18080:127.0.0.1:18080 YOUR_VPS_USER@YOUR_VPS_IP`,
   then visit `http://127.0.0.1:18080/admin` **from your computer**.
   Access is intentionally restricted to localhost; do not expose 18080
   to the public internet. Complete the Stalwart setup wizard, creating a
   permanent admin account and selecting local persistent storage.
5. Set the server hostname to `mail.notify.llama2.com` and primary domain to
   `notify.llama2.com`. Use the domain's DNS records generated by Stalwart.
   Configure a trusted TLS certificate for the SMTP hostname (for example,
   ACME DNS-01). Since existing Caddy owns 80/443, **do not enable Stalwart
   automatic HTTP challenges that would require taking over those ports**.
   If the wizard proposes an HTTP admin listener, keep it restricted and
   disable recovery/bootstrap HTTP access after initial setup.
6. Create the account `no-reply@notify.llama2.com` inside the Stalwart admin.
   Use a strong unique app password with SMTP submission permissions; require
   authentication for SMTP submission and **do not allow anonymous relaying**.
7. Create DNS records via your DNS provider (replace with the VPS's actual IP):

   - `A mail.notify.llama2.com -> YOUR_VPS_IP`
   - `MX notify.llama2.com -> 10 mail.notify.llama2.com` (needed for receiving
     bounces/inbound mail; not necessary to replace any main-domain MX)
   - `TXT notify.llama2.com -> "v=spf1 mx -all"` (adjust based on actual senders)
   - `TXT _dmarc.notify.llama2.com -> "v=DMARC1; p=none"` initially; move to
     quarantine/reject only once you verify alignment
   - `DKIM` TXT records: copy **exact selectors and values** from Stalwart admin,
     never guess them.
   - `PTR` / reverse DNS for the sending IP -> `mail.notify.llama2.com` through
     your VPS provider, with matching forward `A` record.
   - Publish additional Stalwart-recommended records (TLS reporting, MTA-STS)
     as applicable.
8. In **Air Agent > Admin > Password recovery** press **Use open-source Stalwart**.
   This fills in SMTP hostname, user and sender. Paste the app password created
   in Stalwart into **Bot email domain > SMTP password**, then **Save**.
9. Press **Send test email**. This checks SMTP authentication/TLS and that
   the mail server accepted submission; you must **personally verify** the
   email arrives in the admin account inbox, not spam. Follow by testing the
   actual **Forgot password?** flow on a test user account.

## Safety and maintenance

- Backup `stalwart-config` and `stalwart-data` named volumes, encrypted.
- Enable security updates, firewall rules, spam-abuse monitoring and disk alerts.
- Do not put mail credentials or DNS private keys in the GitHub repository.
- A functioning SMTP connection does **not** mean Gmail/Outlook will deliver
  your messages. Reputation, IP history, rDNS, SPF, DKIM and DMARC matter.
- Stalwart full mail setup is a separate deployment with web-admin/DNS work.
  Without it, the preset **does not** make password recovery deliverable.
- Official setup docs: https://stalw.art/docs/install/platform/docker/
- Hostinger port policy: https://www.hostinger.com/support/7854530-is-smtp-port-25-blocked-on-hostinger-vps/
